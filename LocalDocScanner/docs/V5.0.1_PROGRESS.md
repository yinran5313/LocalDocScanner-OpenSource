# 拾页 V5.0.1 修复与验收

2026-10-10；Android 8.0+ / ARM64，versionCode 15，保留 applicationId 和原 Debug 签名，可覆盖安装。重点是实际故障修复及扩大回归范围。

## 本次修复

| 问题 | 修改及源码入口 |
|---|---|
| 首页“导入 / 打开”截字，长操作按钮挤在一行 | `ui/components/AdaptiveActions.kt` 按实际字体测量按钮文字；等宽放置，空间不足时省略装饰图标，再不足时竖排；首页、任务、Office和外部文件底栏接入。 |
| 工具网格、设置选项在窄屏/大字体下拥挤 | `ToolGrid.kt` 按宽度与字体调整列数；`WrappingOptions` 自动换行；复杂弹窗可滚动。 |
| 图片编辑横屏预览被挤压 | `EditScreen.kt` 横屏预览与操作双栏，竖屏保留预览并限制可滚动操作区高度；长增强操作可横向滑动。 |
| 中文文件名显示百分号编码 | `util/DisplayNames.kt` 只解码有效UTF-8中文等字符，保留加号、非法编码及路径符号；不改动原件。 |
| 历史结果只有分享，不能另存 | `OutputHistoryStore.saveCopy` 和 `OutputHistoryScreen` 增加另存到手机；保存更新同一记录，防止同URI复制截断源文件。 |
| PDF非法页码跳转提示藏在弹窗背后 | `PdfReader.kt` 输入框内错误提示与数字键盘；搜索、有效/无效跳转有回归。 |
| 相同PDF对比报“没有生成文件” | `PdfComparison.compare` 生成可预览的零差异报告PDF，差异页数保持0。 |
| 中文表单重复加载完整字体导致内存不足 | `PdfOfficeTools.fillForm` 使用PDFBox间接字体引用和共享资源缓存；保留可填写字体，并验证保存后中文能实际渲染。 |
| medium OCR模型加载产生大块Java堆复制 | `ppocr-sdk/.../ORTSessionManager.kt` 将模型流式写入按版本隔离的codeCache，使用ORT文件会话；错误加载释放已打开会话；兼容API26。 |
| 高挖孔及横屏侧边安全区覆盖内容 | `ui/components/AppSafeFrame.kt` 统一消费顶部/侧边安全区，包含displayCutout；底栏继续处理导航栏及键盘。 |
| 实际系统大字体时标题栏副标题被裁切 | `readableTopBarHeight` 按文字行高计算标题栏高度；首页与通用标题栏接入，增加父容器裁切断言，字体较大时省略首页装饰锁图标。 |

## 验证范围

- 宽度320、360、384、412、600dp × 字体1.0、1.3、1.5、2.0：首页主操作、长操作按钮；设置15种组合，工具网格3种组合。
- 另实际调整模拟器分辨率/密度/系统字体，验证320、384、约412、600dp的4种系统窗口；标题、按钮、父容器裁切及真实安全区检查，检查后恢复系统参数。
- 编辑器320×640、384×640、800×360、600×800及1.0–2.0字体；裁边与增强预览、保存操作。
- 真正窗口的挖孔/导航栏避让；PDF连续拖动停在两页之间、整页吸附、双指/双击缩放、继续滚动、搜索与跳页。
- 原生OpenCV检测/透视/增强、空白书页展平安全回退、连续双页扫描提交、旋转EXIF、页面修改后的OCR失效。
- tiny/medium离线模型实际识别，坐标有效性，可搜索PDF文字提取与渲染。
- 工具暂停/逐页续跑、OCR续跑、输出保存及同URI保护；合并、拆分、压缩、转图片、提取文字、加密、图片转PDF、长图、图片编辑及相同PDF对比的真实处理链。
- 中文AcroForm保存、重开和原生PdfRenderer像素验证；旧DOC/XLS/PPT文字提取。
- JVM全套、Android Lint、Office中文对话框JS、APK资源哈希/JNI/ELF依赖及16KB对齐、版本与签名；公开源码独立恢复构建。

最终计数以 `V5.0.1_TEST_RESULTS.json` 和本地交付记录为准。模拟器组合验证不等于每种厂商手机都验收；扫描质量仅有固定样本，不能代表所有模糊/反光/阴影场景。

## 当前真机边界

已在用户手机的V5.0.0复现并保留首页截字、编码名称等证据，应用数据已做本地私有备份。手机系统目前拒绝ADB安装：`INSTALL_FAILED_USER_RESTRICTED`，新版本覆盖安装与设备回归尚待USB安装权限。未清除原App数据；私人文档、备份、截图和设备日志不进入公开仓库/源码包。

完整Office ARM64引擎的手机编辑保存往返、真实相机拍摄、外部App分享接收、实体打印、海量/超大文件及旧数据库版本迁移仍需要专项验收；本次没有把这些标为已通过。现有V5历史缺口仍见V5进度报告。

## 复用依据

使用现有AndroidX Compose（Apache-2.0）、PDFBox-Android（Apache-2.0）、ONNX Runtime（MIT）API，不新增UI或OCR引擎。

- [Material3 Button.kt](https://github.com/androidx/androidx/blob/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/Button.kt)：按钮内容与padding约束。
- [PDResources.java](https://github.com/TomRoush/PdfBox-Android/blob/master/library/src/main/java/com/tom_roush/pdfbox/pdmodel/PDResources.java)：`getFont` 和间接资源缓存。
- [OrtEnvironment.java](https://github.com/microsoft/onnxruntime/blob/main/java/src/main/java/ai/onnxruntime/OrtEnvironment.java)：`createSession(String, SessionOptions)` 文件加载；已有依赖1.21.1。

本机完整源码包含模型、字体及匹配Office运行资源；公开仓库通过原SHA256资产分卷恢复固定资源。Office完整核心源码仍保留原固定上游来源，本次未重新从Linux全量构建核心。
